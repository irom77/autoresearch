# Chat SFT Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fine-tune a separate conversational derivative of the autoresearch base model with the existing tokenizer and evaluate it reproducibly.

**Architecture:** Plain-text `User:`/`Assistant:` rendering preserves the exact 8,192-token vocabulary. A focused SFT trainer masks prompt tokens, saves a standalone native checkpoint, and a deterministic evaluator records generated replies and resource usage.

**Tech Stack:** Python, PyTorch, existing native checkpoint loader, tiktoken tokenizer, RunPod A40, pytest, Hugging Face Hub.

**Spec:** `docs/superpowers/specs/2026-09-25-chat-sft-design.md`

## Global Constraints

- Preserve the existing 8,192-token tokenizer and 50,332,176-parameter base checkpoint.
- Use plain text conversation delimiters (`User:` and `Assistant:`).
- Save SFT outputs separately from `autoresearch` as `autoresearch-sft`.
- Do not present custom-tokenizer SFT results as official nanochat chat scores.
- Remove the RunPod pod after artifact and log recovery.

## Review Focus

- User-only turns must not contribute to SFT loss — test masked labels.
- A final assistant turn must remain trainable — test assistant labels.
- Empty or malformed conversations must fail clearly — test renderer validation.
- Base metadata must remain distinct from SFT metadata — test checkpoint fields.
- Generation must work after reload — run the evaluator against the saved file.
